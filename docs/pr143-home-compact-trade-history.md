# PR143 — 홈 화면 압축 및 실제 체결 내역

> 후속 수정으로 KIS 홈 거래 내역의 원천을 로컬 주문 증거에서 실제 계좌 조회로 교체했다. 아래는 최초 구현 기록이며, 현재 동작·실계좌 검증·최종 테스트 결과는 [KIS 계좌별 체결 조회 후속 보고서](pr143-kis-broker-executions-followup.md)를 따른다.

작업 브랜치: `pr143-home-compact-trade-history` (기준 `pr142-scheduler-owner-order-sync`). 구현과 테스트만 수행하며 커밋, 푸시, PR 생성, 운영 DB 변경은 하지 않는다.

## 화면 변경

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 운영 모드 | 제목·모드·설명·실행 상태를 여러 행으로 표시 | 제목·모드·LIVE를 같은 행에 두고 실행 상태와 작은 배지를 표시 |
| 운영 모드 높이 | 195px | 100px: 약 48.7% 축소 |
| 자산 현황 | KIS 지표 4개 다음 행에 평가손익 | 넓은 화면에서 지표 5개를 같은 행에 표시 |
| 보유 주식 | 시장 국면 아래, 최대 3개만 표시 | 자산 바로 아래, 처음 3개와 전체 펼치기/접기 |
| 체결 내역 | 홈 전용 조회·표시 없음 | 보유 주식 다음, 기본 접힘, 최근 2건과 기간 전체 요약 |
| 시장 국면·AI | 기존 순서 | 거래 내역 다음에 시장 국면과 최신 AI 결과 |

높이는 같은 1280×1080 Widget 렌더링, 같은 Fake 자산·설정·글꼴로 측정했다. 화면 폭과 글꼴 크기에 따라 배지가 줄바꿈된다. 작은 화면은 안전 상태를 유지하면서 자산 지표를 2~3열로 배치한다. LIVE, 실주문 허용, 긴급 정지는 숨기지 않는다. 기존 운영 모드 선택·실거래 확인 절차와 자동화 프로필 진입은 유지한다.

현재 순서는 헤더/브로커 선택 → 연결 상태 → 운영 모드 → 자동화 프로필 → 자산 현황 → 보유 주식 → 거래 내역 → 시장 국면 → 최신 AI 결과다.

조회 실패나 누락 금액은 `--` 또는 `미확인`으로 표시한다. 평가손익 색상과 KRW/USD 포맷은 유지한다. 보유 주식이 없으면 한 줄로 표시한다.

## 체결 데이터와 계정 범위

기존 `/kis/orders`와 `/users/me/trading/orders`는 최근 주문 시도까지 포함하는 목록이며 기간 전체의 체결 조회·요약·페이지네이션을 보장하지 않는다. 이를 홈 체결 내역으로 재사용하지 않고 인증 필수인 읽기 전용 `GET /trading/fills`를 추가했다.

- SQL 조회부터 관리자 `owner_user_id IS NULL` 또는 현재 일반 사용자 ID로 제한한다. 관리자의 환경 기반 KIS 계정과 사용자 DB 계정을 합치지 않는다. 클라이언트가 전달한 사용자 ID로 범위를 넓히지 않는다.
- 선택한 브로커·시장과 서버에서 확인한 계정 환경만 조회한다. 일반 사용자의 환경은 자기 브로커 자격증명 메타데이터에서 확인한다. 원본 자격증명 복호화나 브로커 연결은 필요하지 않다.
- KIS는 PR142 동기화가 저장한 `last_sync_payload.matched_order`와 `inquiry`를 사용한다. 사용자별 owner/provider/broker_account_id/environment/complete 증거가 일치해야 한다.
- 주문번호·종목·매수/매도·주문일·요청 수량과 브로커의 양수 체결 수량을 검증한다. 상태 문자열이나 AI 추천만으로 체결을 만들지 않는다.
- 거절, 안전 게이트 거절, REQUESTED, 체결 수량 0, 미검증 UNKNOWN_STALE, 드라이런, 시뮬레이션, 분석 결과는 표시하지 않는다. 검증된 부분 체결은 실제 체결 수량만 사용하며, 이후 취소된 주문도 이미 체결된 부분만 표시한다.
- KIS 일별 조회는 주문별 누적 체결 증거이므로 같은 거래일·브로커 주문번호는 한 항목으로 합친다. 부분 체결 스냅샷을 더해서 중복 계산하지 않는다. 건수는 검증된 체결 주문의 수다.
- Alpaca도 환경과 브로커 주문 객체의 ID·종목·방향·체결 수량·시간을 검증할 수 있는 저장 증거만 읽는다. 최신 동기화 객체를 우선한다. 환경이나 원본 체결 증거가 없는 기존 기록은 추정하여 노출하지 않는다.
- 응답은 종목, 방향, 실제 체결 수량, 확인된 평균가/금액, 거래일/확인된 시각, 부분 체결 여부만 허용한다. API 키·토큰·계좌번호·브로커 원본 응답은 반환하지 않는다.

홈 진입과 새로고침은 이 GET만 호출한다. 체결 내역 때문에 동기화 POST, 매수·매도·취소 API를 호출하지 않는다. 조회 오류는 자산과 AI 표시를 막지 않는다.

## 날짜와 조회 범위

`period=today|week|month|year`, `limit=1..100`(기본 20), `offset>=0`, 선택적 `as_of`를 지원한다. 오늘은 KST 00:00부터 현재까지다. 1주·1개월·1년은 오늘을 포함한 최근 7·30·365개 KST 달력 날짜의 00:00부터 현재까지다. 경계는 응답의 `start_at`/`end_at`으로 확인할 수 있다. 다음 페이지는 첫 페이지의 `end_at`을 `as_of`로 보내 조회 도중 날짜 경계가 바뀌는 것을 막는다.

기간 전체의 서버 보유 증거를 검증하고 중복 제거·기간 필터·정렬·합계를 계산한 뒤 페이지를 자른다. 최근 20건을 프런트엔드에서 연간 데이터처럼 필터링하지 않는다. 요약 건수와 매수/매도 금액은 현재 페이지가 아닌 선택 기간 전체 기준이다. 금액이 확인되지 않은 거래가 있으면 해당 방향의 합계도 `미확인`으로 표시한다.

KIS 일별 체결 응답에 정확한 체결 시각이 없으면 `filled_at=null`, `time_precision=day`와 검증된 거래일을 반환하고 화면에 **체결 시각 미확인**을 표시한다. `ord_tmd`는 주문 시각이고 기존 관리자 `OrderLog.filled_at`은 동기화 시각일 수 있으므로 체결 시각으로 쓰지 않는다. 확인된 `ccld_tmd`가 있는 경우에만 KST 시각을 표시한다. 같은 날짜 안에서 시각이 없는 거래의 체결 순서는 보장할 수 없다.

조회 범위는 **이 서버에 브로커 체결 증거가 저장된 주문**이다. 외부 앱에서만 거래한 주문, 아직 동기화하지 않은 주문, 증거가 유실된 과거 거래까지 계좌 전체 내역이라고 표시하지 않는다. 펼친 카드에 이 범위를 안내한다. 수수료와 실현손익은 계산하지 않는다.

## 상태 관리

기존 DashboardController가 선택 기간, 페이지, 로딩·오류·더 보기 상태를 관리한다. 카드 펼침과 보유 주식 펼침은 UI 상태로 유지한다. Pull-to-refresh는 내역을 다시 조회한다. 브로커·로그인 계정 변경 시 즉시 이전 내역을 지우며 요청 버전·세션·브로커 문맥을 확인해 늦게 도착한 응답을 버린다. 일반 사용자 모드 조회도 계정이 바뀐 뒤 이전 설정을 덮어쓰지 않는다.

## 운영 적용 전 확인

실제 적용 시 관리자와 test01에 각각 로그인해 자기 KIS 환경·보유 주식·체결만 보이는지 확인한다. 기존의 승인된 동기화 경로가 저장한 증거를 대상으로 기간과 더 보기를 확인한다. 체결 시각이 없는 기록은 날짜만 보이는 것이 정상이며, 증거가 없는 기록을 홈 조회가 자동 복구하거나 동기화하지 않는다. 기존 모드 선택과 LIVE 확인 창, 긴급 정지 및 실주문 상태, 좁은 화면의 줄바꿈을 확인한다.
